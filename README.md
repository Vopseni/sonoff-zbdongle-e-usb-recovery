# SONOFF ZBDongle-E — USB Recovery

**Практическое исследование восстановления Zigbee-координатора SONOFF ZBDongle-E после перезагрузки Raspberry Pi без физического переподключения USB.**

## О проекте

В этом проекте исследуется проблема нестабильной работы USB-координатора SONOFF Zigbee 3.0 USB Dongle Plus V2 (EFR32MG21) при использовании Raspberry Pi 3 и Zigbee2MQTT.

Основная задача — установить причины зависания координатора и разработать воспроизводимый способ восстановления его работоспособности после перезагрузки Raspberry Pi.

Особое внимание уделяется программному USB Reset, взаимодействию USB-устройства с Docker и автоматизации запуска Zigbee2MQTT.

## Аппаратная конфигурация

| Компонент | Модель |
|---|---|
| Одноплатный компьютер | Raspberry Pi 3 Model B Rev 1.2 |
| Zigbee-координатор | SONOFF ZBDongle-E |
| Микроконтроллер | Silicon Labs EFR32MG21 |
| Операционная система | Debian GNU/Linux 13 |
| Архитектура | ARM64 (aarch64) |
| Контейнеризация | Docker |
| Zigbee ПО | Zigbee2MQTT |

## Прошивка координатора

В ходе исследования использовалась прошивка:

- Zigbee NCP 8.0.2.0
- UART 115200
- Software Flow Control

## Обнаруженная проблема

После перезагрузки Raspberry Pi USB-координатор может определяться операционной системой, но при последующем запуске Zigbee2MQTT наблюдается зависание.

Для восстановления работы требовалось физически отключить и снова подключить USB-координатор.

## Найденный способ восстановления

В ходе экспериментов проверена возможность программного сброса USB-устройства с помощью утилиты `usbreset`.

Команда:

```bash
sudo usbreset 1a86:55d4
```

Полученный результат:

```text
Resetting SONOFF Zigbee 3.0 USB Dongle Plus V2 ... ok
```

17 ноября 2026 года эксперимент №5 подтвердил возможность восстановления координатора после перезагрузки Raspberry Pi без физического переподключения USB.

Проверенная последовательность:

1. Штатная остановка контейнера Zigbee2MQTT.
2. Перезагрузка Raspberry Pi с подключённым координатором.
3. Ожидание полной загрузки операционной системы.
4. Выполнение программного USB Reset.
5. Запуск контейнера Zigbee2MQTT.

**Важно:** точная причина зависания пока не установлена. Программный USB Reset рассматривается как экспериментально проверенный способ восстановления в исследованной конфигурации, а не как универсальное решение для всех систем.
