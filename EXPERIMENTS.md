# Журнал экспериментов SONOFF ZBDongle-E

**Проект:** восстановление работоспособности SONOFF ZBDongle-E после перезагрузки Raspberry Pi.

**Дата исследования:** 17 ноября 2026 года.

## 1. Исходная конфигурация

| Параметр | Значение |
|---|---|
| Компьютер | Raspberry Pi 3 Model B Rev 1.2 |
| ОС | Debian GNU/Linux 13 (Trixie) |
| Архитектура | aarch64 |
| Координатор | SONOFF ZBDongle-E |
| Чип | Silicon Labs EFR32MG21 |
| USB VID:PID | 1a86:55d4 |
| Последовательный порт | /dev/ttyACM0 |
| Прошивка | Zigbee NCP 8.0.2.0 |
| Скорость UART | 115200 |
| Flow Control | Software |
| Контейнер | z2m_EFR32MG21 |

## 2. Постановка проблемы

После перезагрузки Raspberry Pi координатор SONOFF ZBDongle-E мог определяться операционной системой, но при запуске Zigbee2MQTT возникала проблема взаимодействия с USB-устройством.

В отдельных испытаниях наблюдалось зависание системы.

Для восстановления работы ранее приходилось физически переподключать координатор.

Цель исследования — проверить возможность восстановления USB-устройства программным способом.

## 3. Эксперимент №1. Проверка USB-устройств после загрузки

**Задача:** проверить, обнаруживает ли операционная система USB-устройства после перезагрузки Raspberry Pi.

**Условия:**
- Raspberry Pi перезагружена.
- SONOFF оставался физически подключённым.
- Автоматический запуск Zigbee2MQTT отключён через RestartPolicy=no.

**Результат:**

После загрузки были обнаружены:

- Arduino CH340 — /dev/ttyUSB0.
- SONOFF EFR32MG21 — /dev/ttyACM0.

Постоянные пути устройств в /dev/serial/by-id/ также присутствовали.

**Вывод:** USB-устройство обнаруживается операционной системой. Однако само обнаружение ещё не подтверждает готовность координатора к работе с Zigbee2MQTT.

## 4. Эксперимент №2. Проверка программного USB Reset

**Задача:** проверить возможность сброса USB-устройства без физического отключения кабеля.

Использовалась команда:

```bash
sudo usbreset 1a86:55d4
```

**Полученный результат:**

```text
Resetting SONOFF Zigbee 3.0 USB Dongle Plus V2 ... ok
```

**Вывод:** утилита обнаружила соответствующее USB-устройство, а операция программного USB Reset завершилась успешно.

Важно: данный результат подтверждает выполнение USB Reset, но не доказывает физическое отключение питания координатора.

## 5. Эксперимент №3. Исследование запуска Zigbee2MQTT

**Задача:** проверить зависимость результата запуска Zigbee2MQTT от предварительной инициализации USB-координатора.

В ходе испытаний было замечено, что запуск Zigbee2MQTT без предварительного восстановления USB-устройства мог сопровождаться зависанием Raspberry Pi.

При использовании предварительного USB Reset наблюдался другой результат.

Точные условия и результаты отдельных промежуточных запусков требуют дополнительного документирования.

## 6. Эксперимент №4. Проверка утилиты usbreset

**Дата:** 17 ноября 2026 года.

Выполнен программный сброс SONOFF ZBDongle-E:

```bash
sudo usbreset 1a86:55d4
```

Получено сообщение:

```text
Resetting SONOFF Zigbee 3.0 USB Dongle Plus V2 ... ok
```

**Результат:** программный USB Reset выполнен успешно.

**Вывод:** утилита может использоваться для программного сброса исследуемого USB-устройства.

## 7. Эксперимент №5. Восстановление после перезагрузки Raspberry Pi

**Дата:** 17 ноября 2026 года.

**Цель:** проверить восстановление координатора без физического переподключения USB.

### Последовательность действий

1. Контейнер z2m_EFR32MG21 был штатно остановлен.
2. Raspberry Pi перезагружена.
3. SONOFF оставался физически подключённым.
4. После загрузки системы выполнен USB Reset:

```bash
sudo usbreset 1a86:55d4
```

5. Получен результат:

```text
Resetting SONOFF Zigbee 3.0 USB Dongle Plus V2 ... ok
```

6. После этого был запущен контейнер Zigbee2MQTT.

### Результат

Эксперимент завершился успешно.

Координатор восстановил работоспособность без физического переподключения USB-кабеля.

## 8. Эксперимент №6. Взаимодействие Docker и USB

**Цель:** исследовать поведение Docker-контейнера Zigbee2MQTT при взаимодействии с USB-координатором и корректном завершении работы контейнера.

В исследовании рассматриваются:
- порядок остановки контейнера;
- поведение USB-устройства после завершения контейнера;
- запуск контейнера после перезагрузки Raspberry Pi;
- необходимость предварительного USB Reset;
- возможность автоматизации восстановления.

Эксперимент находится в стадии исследования.

Подтверждённые результаты будут добавлены после завершения испытаний.

## 9. Предварительный итог

На основании проведённых испытаний установлено:

1. Операционная система может обнаруживать USB-координатор после перезагрузки.
2. Наличие последовательного порта не гарантирует успешного взаимодействия с Zigbee2MQTT.
3. Программный USB Reset с помощью usbreset выполняется успешно.
4. В эксперименте №5 подтверждено восстановление координатора без физического переподключения.
5. Последовательность «загрузка Raspberry Pi → USB Reset → запуск Zigbee2MQTT» показала работоспособность в исследованной конфигурации.

**Причина первоначального зависания пока не установлена.**
